## Critical char-count rule (from form)

> "A character includes a space, punctuation, letter, number, or symbol; additionally, **blank line spaces between paragraphs count toward character count and should not be used.**"

All `PASTE THIS` blocks in this directory have **blank lines stripped** — paragraphs are separated by a single newline only. The DIP textarea will render single newlines as line breaks; reviewer experience is preserved while character cost is minimized.

**Do not edit the paste blocks to add blank lines back in.** If you do, you may bust the cap. Tightest field after the re-center is the **Project Synopsis (1,964 / 2,000 = 36-char headroom)**; the rest have ≥ 80 chars of headroom.

## Troubleshooting

- **DIP says over cap, file says under cap.** Most likely cause: smart-quote conversion (DIP may auto-convert `"foo"` to `"foo"`, adding bytes) or em-dash conversion. Open the file, search for `"`, `'`, `—`, `–`, replace with ASCII equivalents `"`, `'`, `-`, `-`. Re-count, re-paste. Worst-case fallback: trim a sentence from the end of the paragraph that's least load-bearing.
- **DIP character counter doesn't update.** Click into the field, click out (focus loss usually triggers recount). If still wrong, refresh the page (you'll lose unsaved changes — Save Draft first if possible).
- **Browser tab closes / session expires.** Per form: "Clicking Next saves your data." Anything you've Next-saved is preserved. Anything in flight is lost. Log back in, navigate to the proposal, resume.

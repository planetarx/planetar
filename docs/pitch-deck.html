01The Problem

Sensor fusion is stuck in batch.

Defence and maritime operators have more feeds than ever — and a slower, blinder picture than the threat requires.

Siloed
AIS, SAR, EO, radar, acoustic, RF — each locked in its own tool, its own vendor, its own format. Nothing shares a clock.
Too slow
Fusion happens hours later, in batch pipelines. The decisive moment has passed before the data is even joined.
Unexplainable
No record of why a conclusion was reached. An operator cannot trust — or defend — what they cannot trace.
Concretely: a vessel switches off its AIS transponder and vanishes from the maritime picture — the standard move for illegal fishing, sanctions evasion, and sovereignty-testing incursions. Today, finding it again is manual, late, and unprovable.
02The Solution

One bus. Every modality. Full provenance.

planetar makes every signal a typed message on a single, ultra-fast bus — so fusion is real-time and every output is traceable by construction.

Typed envelopes
A SAR chip, an AIS ping, a hydrophone hit, an algorithm's output, an analyst's chat message — all become one typed envelope with nanosecond timestamps and lineage IDs.
Composable viewers
Map, timeline, entity card, waveform, channel — every viewer is just a consumer of the bus. Add a sensor, every view updates live.
Provenance graph
A provenance-tracked entity graph resolves identity across modalities. Every conclusion clicks back to its raw inputs.
Think Slack × Palantir — but rebuilt from the transport layer up, fast enough to run live at the edge.
03Why It's Hard To Copy

The bus is the thesis.

The entire platform rests on one piece of genuinely hard engineering — a new bus design we call the Distributed Disruptor, written from scratch in C.

80–140 ns
P50 LATENCY — FASTER THAN A CPU CONTEXT SWITCH
~1.9M msg/s
SUSTAINED THROUGHPUT, SINGLE COMMODITY HOST
~1,200 LOC
PURE C — NO DEPENDENCIES BEYOND LIBC
  • A new pattern — the Distributed Disruptor. The classic LMAX Disruptor is a single-process ring buffer; planetar meshes many Disruptors into one fabric, extending the nanosecond hot path across hosts and edge nodes.
  • Lock-free, zero-copy. Shared memory + TCP + UDP transports and a durable write-ahead log with CRC32 checks — so whatever AI model you bolt on rides the bus at zero meaningful overhead.
  • Edge-ready. A laptop today, an edge node tomorrow — no cluster, no cloud dependency, low size-weight-and-power.

Benchmark: 1M-message run on the predecessor build (zbroker0), commodity Linux, 2026-04-27. planetar-broker re-benchmark in progress.

08Why It Compounds

The moat gets deeper with use.

Architecture moat
The nanosecond bus is hard to build and far harder to retrofit. Competitors start from batch pipelines — they cannot bolt real-time on after the fact. We start where they would have to finish.
Data network effect
Every deployment enriches the entity graph. Each new modality and each new vessel observed makes identity resolution sharper — for every customer. The product improves as it spreads.
Open-core, by design. The code is AGPL — and because we control it, we dual-license it to ourselves: our own product runs unencumbered. Any competitor who builds on planetar must open their entire stack. Open source earns adoption and trust; copyleft defends it.
